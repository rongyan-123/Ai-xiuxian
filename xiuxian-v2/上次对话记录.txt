【Playwright E2E 重写 — 发现三个致命假阳性问题】

原 e2e/api-robustness.spec.ts 存在三个关键 bug：

1. 输入定位器不匹配：
   'textarea, [contenteditable="true"], input[type="text"]' 从来匹配不到
   @base-ui/react 的 Input 组件（渲染为 <input data-slot="input">）
   导致 sendMessage() 每次都静默跳过，测试从未真正执行输入

2. page.route() 与 Next.js 16 Turbopack 不兼容：
   Playwright 的 route 拦截无法捕获 Turbopack dev server 的 fetch() 请求
   所有 route 都显示 Intercepted: false

3. 断言假通过：
   expect(content).toBeTruthy() 永远通过（页面总有内容）
   即使输入从未发送，测试也显示通过

【重写方案】
- INPUT_SELECTOR = '[data-slot="input"]'（匹配 @base-ui/react Input）
- 改用 page.evaluate() 覆盖 window.fetch（绕过 Turbopack 限制）
- 具体断言：toContain('青云山')、toMatch(/Connection|错误|失败|error/i)
- getToPlayingState() 补充 phase: 'PLAYING'（之前缺失，页面停在角色创建）
- sendMessage() 优雅处理移动端（input 不可见时 return false）
