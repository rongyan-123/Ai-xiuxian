## 一、项目背景

当前 `xiuxian-v2` 是一个4节点线性 LangGraph 流水线（RAG检索 → LLM生成 → 规则引擎 → DB持久化），不是真正的Agent框架。本计划旨在将其完全重写为正式的Agent框架。

## 二、已完成的架构设计

以下模块已完成头脑风暴，设计思路记录在 `docs/architecture-brainstorm-log.md`：

| # | 模块 | 设计要点 |
|---|------|---------|
| 1 | Agent循环 | for循环 + 工具调用 + Done Tool + 临时消息 |
| 2 | NPC分级 | T3(完整Agent)/T2(混合)/T1(模板)/T0(宏观) |

## 六、技术风险

1. **LLM调用成本** — Region DM每天2次调用/区域，T2 NPC每天1次。10个区域+50个T2 NPC = 70次/天。需要成本预估。
2. **上下文膨胀** — 几百回合后即使有压缩，也可能超出窗口。需要实测。
3. **工具调用稳定性** — LLM可能返回格式不正确的工具调用。需要健壮的解析+重试。
4. **横向时间一致性** — 所有NPC同时推进时的因果顺序。需要事务性保证。
5. **双模型延迟** — 快速模型+强力模型串行调用增加总延迟。需要考虑并行化。
